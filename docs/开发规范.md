# 微信小程序开发规范与注意事项

> 适用仓库：`zhibo-wxmini`（原生微信小程序）  
> 本机开发验证；未明确要求时不要 `git commit` / `push`。  
> 若用户要求提交，前缀使用 `[wxmini-grok]`。

---

## 1. 中文注释（硬性要求）

**函数、常量必须写中文注释。** 这是本项目硬性约定，提交前与自检时优先核对。

### 1.1 写什么

| 对象 | 注释应说明 |
|------|------------|
| 函数 | 用途；关键参数含义与类型；返回值含义；副作用（如写 storage、跳转） |
| 常量 | 用途；配置键 / storage 键含义；取值范围或可选值 |
| 配置对象字段 | 每个关键键的业务含义（尤其 `config/env.js` 中的环境与域名） |

避免空泛注释（如「定义变量」「返回结果」）。注释应能让后来者在不读完整实现的情况下理解「为什么存在」和「怎么用」。

### 1.2 写法建议

- 优先使用 `/** ... */`（函数、导出常量、模块顶栏说明）
- 行内补充可用 `//`
- 参数 / 返回值可用 JSDoc 风格：`@param`、`@returns`（中文描述）

示例：

```js
/** 本地存储键：观众 accessToken */
const ACCESS_KEY = 'viewerAccessToken';

/**
 * 按当前环境 + 服务名取 baseURL。
 * @param {string} [service=live] 服务名
 * @returns {string}
 */
function getBaseURL(service) {
  // ...
}
```

### 1.3 适用范围

- **必须注释**：业务 JS —— `app.js`、`config/`、`utils/`、`pages/` 下业务脚本
- **不要求**：`node_modules`、第三方生成物、微信开发者工具自身文件

新增或修改函数 / 常量时，同步补全或更新中文注释；删改逻辑后勿留下过时注释。

## 2. 项目约定

### 2.1 技术栈与范围

- **原生微信小程序**（非 uni-app / Taro）
- 只改本仓库 `zhibo-wxmini`；不要擅自改 `zhibo-backend`、`zhibo-frontend`、`zhibo-shared` 等（除非用户明确授权）
- 本机开发与验证；**未明确要求时不要 git commit / push**
- 若用户要求提交：commit 前缀 `[wxmini-grok]`（仅用户要求时）

### 2.2 环境切换

环境名：`local` / `test` / `prod`。

解析顺序（见 `config/env.js`）：

1. `FORCE_ENV` 非空时优先强制：`'local' | 'test' | 'prod'`
2. 否则用 `wx.getAccountInfoSync().miniProgram.envVersion`：
   - `release` → `prod`
   - `trial` → `test`
   - `develop` → `local`
3. 拿不到 / 未知 → `local`

本机调试需要固定环境时，改 `FORCE_ENV`；上线前确认 `FORCE_ENV` 为 `null`，避免误强制。

### 2.3 多域名请求

- 环境与各服务 `baseURL`：`config/env.js`（`getBaseURL(service)`）
- **`baseURL` 含 API 版本前缀**（当前 `/api/v1`，如 `http://127.0.0.1:8082/api/v1`）。升级 v2 只改 `ENV_CONFIG.services`，`api/` 路径不要写 `/api/v1`
- `api/` 业务路径从 `/viewer/...` 起（对齐前端 D63）
- 统一请求封装：`utils/request.js`
- 业务服务名至少包含 `live`（live-service）；后续可按服务名扩展
- `local` 开发者工具可勾选「不校验合法域名」；`test` / `prod` 须配置 HTTPS 合法域名，真机不可用 `127.0.0.1`

### 2.4 观众登录

- 本地 storage 键使用 `viewer*` 前缀（如 `viewerAccessToken`、`viewerRefreshToken`、`viewerPhoneMasked`），见 `utils/auth.js`
- 接口路径：`/viewer/auth/*`（login / refresh / me），完整 URL = baseURL + 路径
- `401`：**单次** refresh 后重放请求；并发 401 共用同一次 refresh；刷新失败清会话并跳转登录页

### 2.5 ID 与数值类型（D56）

- 后端 `INT` / `BIGINT`（如 `rs_mainkey_id`）在小程序侧用 **number**
- **不要**当成超长 decimal 字符串传来传去
- UUID / `VARCHAR` 类主键仍用 string

### 2.6 上传（D60 / 观众中转）

- 对象键前缀前端自定（`ViewerObjectKeyPrefix`），对齐 API约定「对象 key 目录」，与管理端同一做法；**不**从 tos-sts 取前缀
- `proxy`：拼 `objectKey` → `POST .../uploads/file?biz=`（`file` + `objectKey`）
- `direct`：`GET .../tos-sts?biz=` 只拿凭证 → PutObject（同一套前端拼好的 `objectKey`）
- 两条都拿到 `objectKey`、`url`、`location` 后再调业务接口
- `biz`：`1` 头像 / `2` 意见反馈截图
- 头像落库：`PUT .../profile/update` 同时传 `avatarUrl` 和 `avatarObjectKey`
- 不要再为单个功能加专用上传接口，也不要走微吼上传

### 2.7 图片格式

- 使用 **PNG**（或 JPEG 等小程序友好格式）
- **不要用 SVG**（小程序不支持或表现差）

### 2.8 布局量纲

- 设计稿宽度约 **750rpx**
- 按钮、协议勾选区等宽度宜对齐；过宽会溢出可视区域

## 3. 踩过的坑

以下均来自本会话真实问题，写文件 / 改样式前请对照检查。

### 3.1 WXSS UTF-8 BOM

**现象**：编译报 `unexpected �`，或文件首行变成 `﻿page`（BOM 被当成字符）。

**原因**：PowerShell `Set-Content -Encoding UTF8` 会写入带 BOM 的 UTF-8。

**正确写法**（无 BOM）：

```powershell
$utf8NoBom = New-Object System.Text.UTF8Encoding $false
[System.IO.File]::WriteAllText($path, $content, $utf8NoBom)
```

写 `.wxss` / `.wxml` / `.js` / `.md` 时一律用 **UTF-8 无 BOM**。写完可用字节检查：文件头不应是 `EF BB BF`。

### 3.2 WXML 根标签漏 `<`

**现象**：编译报 `get tag end without start`。

**原因**：根节点写成了 `view class="page">`，漏了起始的 `<`。

**注意**：改完 WXML 后扫一眼每个标签是否成对、是否以 `<` 开头；尤其手写或脚本拼接时。

### 3.3 原生 `button` 宽度被默认样式覆盖

**现象**：只写 `.btn { width: xxx }`，按钮宽度看起来「不生效」；曾误以为 rpx 单位无效。

**正确做法**：

```css
button.btn {
  width: 100% !important;
}
```

用父级（如 `.actions`）的左右 `padding` 控制与屏幕边缘的间距，而不是只依赖子级 `width` 的 rpx 绝对值硬凑。

### 3.4 本机 `D:\` 路径与 Read / CopyToBox

**现象**：`Read` / `CopyToBox` 读不了 `D:\...`（路径在 local-exec root 外）。

**做法**：对本机已注册机器，用 **Shell + machineId** 读写（如 `Get-Content` / `WriteAllText`）。不要反复用对沙箱路径的假设去碰本机盘符。

### 3.5 其它短提醒

- 设计稿宽约 750rpx，按钮过宽会溢出
- 协议勾选区宽度宜与主按钮对齐，避免左右错位
- 改 WXSS 后若出现怪字符，先查 BOM，再查编码

## 4. 自检清单（可对照）

开发或改完一版后，快速核对：

- [ ] 新增/修改的函数、常量已写**中文注释**（用途、参数、返回值或键含义）
- [ ] 未对 `node_modules` 提注释要求；业务 JS 已覆盖
- [ ] 环境逻辑走 `config/env.js`，未硬编码域名到页面
- [ ] 请求走 `utils/request.js`；401 仅单次 refresh
- [ ] ID：INT/BIGINT 用 number，未当超长字符串
- [ ] 上传原则：TOS STS，未走业务 `POST /api/uplo…`
- [ ] 图片为 PNG 等，未用 SVG
- [ ] 写入的源码 / 样式 / 文档为 **UTF-8 无 BOM**
- [ ] WXML 标签完整（无漏 `<`）
- [ ] 原生 `button` 宽度用 `button.xxx { width: … !important }` + 父级 padding
- [ ] 未在用户未要求时执行 `git commit` / `push`
