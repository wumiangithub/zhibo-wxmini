| 接口 | 请求要点 | 响应要点 |
|------|----------|----------|
| POST `/api/v1/viewer/auth/wechat-login` | `{}` / 无 code | `400`「缺少微信登录凭证」 |
| 同上 | `{"code":"x","agreed":false}` | `400`「请先阅读并同意用户协议和隐私协议」 |
| 同上 | `{"code":"fake_test_code","agreed":true}` | `500`「观众登录暂不可用」 |
| POST `/api/v1/viewer/auth/phone-login` | `{}` | `400`「请先阅读并同意…」 |
| 同上 | 缺 `phoneCode` / 缺 `loginCode`（agreed=true） | `400`「缺少手机号授权凭证」/「缺少微信登录凭证」 |
| 同上 | fake codes + agreed | `500`「观众登录暂不可用」 |
| POST `/api/v1/viewer/auth/refresh` | `{}` | `400`「登录状态已失效，请重新登录」 |
| 同上 | bad tokens | `401`「刷新凭证无效或已过期」 |
| GET `/api/v1/viewer/auth/me` | 无 Authorization / 坏 Bearer | `401`「未登录」 |

## 2026-10-23 环境自动选择（wx envVersion）

状态：**已完成（本仓）**。未 git commit（用户未授权）。

### 自动切换规则

`config/env.js` 在模块加载时 `resolveEnv()`：

1. **手动覆盖优先**：`FORCE_ENV = 'local' | 'test' | 'prod'` 有值时直接用，忽略微信判断（本机调试用）。
2. **否则读微信**：`wx.getAccountInfoSync().miniProgram.envVersion`
   - `release` → **prod**
   - `trial`（体验版）→ **test**（域名仍可为空占位）
   - `develop`（开发版/开发者工具）→ **local**
3. 拿不到 `wx` / 未知版本 → **local**

开发者工具里一般为 `develop` → `local`，符合预期。`utils/request.js` 仍只调 `getBaseURL`；prod/test 的 `live` 为空时，release 下请求失败属预期，上线前填正式 HTTPS 域名。

### 手动覆盖怎么用

打开 `config/env.js`：

```js
const FORCE_ENV = null;       // 自动（推荐）
// const FORCE_ENV = 'local'; // 强制本机
// const FORCE_ENV = 'test';  // 强制测试
// const FORCE_ENV = 'prod';  // 强制生产
```

改完重新编译即可。勿在本轮 git commit。
